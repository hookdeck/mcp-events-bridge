# MCP client libraries with MCP Events

Three TypeScript MCP client libraries can subscribe to the bridge's events. Each one's support is experimental and may change.

| Library | Tested | Delivery with the bridge | Follows |
| --- | --- | --- | --- |
| [Vercel AI SDK](https://ai-sdk.dev/docs/ai-sdk-core/mcp-events), `@ai-sdk/mcp` | 2.0.84 | Webhook | The design sketch |
| [Mastra](https://github.com/mastra-ai/mastra/pull/27330), `@mastra/mcp` | 2.5.0 | Poll or webhook | SEP-3415 |
| [TanStack AI](https://github.com/TanStack/ai/pull/1816), `@tanstack/ai-mcp` | 1.0.0 | Webhook | SEP-3415 |

**Tested:** each against a local bridge on 26 Oct 2026, with a small Node script: list the events, subscribe to `fills.order.filled` for one symbol, receive a signed fill, refresh (where the library has it), unsubscribe.

## What they have in common

- **Authentication:** send `BRIDGE_MCP_SECRET` as `Authorization: Bearer <BRIDGE_MCP_SECRET>` to `https://<bridge>/mcp` (or `http://127.0.0.1:8080/mcp` for a local bridge). Each library takes headers on its HTTP transport, as below. Keep the secret in your server's environment.
- **The callback URL** must be public HTTPS, and your code serves it:
  - **With a deployed bridge:** a route on your own server, for example `https://<your server>/mcp-events`.
  - **With a local bridge, on the same machine:** call the bridge's `create_tunnel_url` tool once (`agent`, `name`, `port`: the port your receiver listens on, `path: '/'`), and use a path under the URL it returns as the callback: `https://hkdk.events/<id>/mcp-events`. The bridge runs `hookdeck listen` to your port and forwards the path and query string. Use a path under the tunnel URL, not the URL alone: the AI SDK and TanStack AI add a query string, and the bridge recognizes its tunnel URL followed by a path.
- **The signing secret** is generated by the library, one per subscription, and kept in its store. The store holds secrets: keep it on the server, and make it durable in production (the examples use memory).
- **Receivers verify signatures** on the raw body. Pass the request through untouched, as a Web `Request`.
- **`webhook-id`:** the AI SDK and TanStack AI reject a delivery whose `webhook-id` isn't its `eventId`. The bridge sends the `eventId` as `webhook-id`, so this works; a bridge that sent a per-message id, as SEP-3415's latest text asks, wouldn't.
- **Dedupe** by subscription and `eventId`: deliveries are at least once.

The examples below wrap a Node `http` request as a Web `Request`. In a framework that already has one (Next.js route handlers, Hono, Remix), pass it straight to the library's handler.

```ts
// Node http -> Web Request, for the receivers below.
async function toRequest(req: http.IncomingMessage, port: number) {
  const chunks: Buffer[] = [];
  for await (const chunk of req) chunks.push(chunk as Buffer);
  return new Request(`http://localhost:${port}${req.url}`, {
    method: req.method,
    headers: req.headers as Record<string, string>,
    body: req.method === 'POST' ? Buffer.concat(chunks) : undefined,
  });
}
```

## Vercel AI SDK

Webhook delivery only. `experimental_createMCPEventWebhook` verifies each delivery and calls `onEvent`; it doesn't run an agent itself.

```ts
import { experimental_createMCPClient as createMCPClient, experimental_createMCPEventWebhook as createMCPEventWebhook } from '@ai-sdk/mcp';

const store = myDurableStore; // Experimental_MCPEventStore: get, getById, set, update, delete

const webhook = createMCPEventWebhook({
  store,
  async onEvent({ subscription, event }) {
    // event.eventId, event.name, event.data; resolve only once the event is safely handled or queued
  },
});
// Serve POST <callback path> with: res <- await webhook(request)

const client = await createMCPClient({
  transport: { type: 'http', url: 'https://<bridge>/mcp', headers: { Authorization: `Bearer ${process.env.BRIDGE_MCP_SECRET}` } },
  experimental_events: { store },
});
const { events } = await client.experimental_events.list();
const sub = await client.experimental_events.subscribe({
  name: 'resend.email.received',
  arguments: { from: 'alice@example.com' },
  delivery: { mode: 'webhook', url: 'https://<your callback URL>' },
});
// Later: client.experimental_events.refresh({ id: sub.id }) before sub.refreshBefore; unsubscribe({ id: sub.id }).
```

**Success:** your handler answers `204`, and `onEvent` gets the event. Deliveries keep arriving after `client.close()`, until you unsubscribe or the subscription expires (30 days by default; refresh before `refreshBefore`).

## Mastra

Mastra's `MCPClient` subscribes with webhook delivery when you give it a `webhook` URL, and polls otherwise. Poll mode needs no public URL at all, so it's the simplest with a local bridge. A subscription is an async iterator.

```ts
import { MCPClient } from '@mastra/mcp';

const mcp = new MCPClient({
  servers: {
    bridge: { url: new URL('https://<bridge>/mcp'), requestInit: { headers: { Authorization: `Bearer ${process.env.BRIDGE_MCP_SECRET}` } } },
  },
  webhook: { url: 'https://<your callback URL>' }, // omit to poll
});
// With webhook: serve POST <callback path> with: res <- await mcp.events.handleWebhook(request)

const sub = await mcp.events.subscribe('bridge', 'resend.email.received', { from: 'alice@example.com' }, { delivery: 'webhook' }); // or 'poll'
for await (const event of sub) {
  // event.eventId, event.name, event.data; persist sub.cursor (poll) to resume later
}
// sub.cancel() stops it (and unsubscribes, for webhook).
```

**Success:** the loop yields the event. Mastra reads only SEP-3415's capability, `extensions["io.modelcontextprotocol/events"]`, which the bridge declares alongside the older `events`.

## TanStack AI

Webhook delivery. The handler verifies each delivery and calls `onEvent` with the event and its `messageId` (the `webhook-id`).

```ts
import { createMCPClient } from '@tanstack/ai-mcp';
import { createMCPEventWebhook, inMemoryMCPEventStore } from '@tanstack/ai-mcp/events';

const store = inMemoryMCPEventStore(); // use durable storage in production
const webhook = createMCPEventWebhook({
  store,
  onEvent: async ({ event, messageId, subscription }) => {
    // event.eventId, event.data
  },
});
// Serve POST <callback path> with: res <- await webhook(request)

const mcp = await createMCPClient({
  transport: { type: 'http', url: 'https://<bridge>/mcp', headers: { Authorization: `Bearer ${process.env.BRIDGE_MCP_SECRET}` } },
  experimental_events: { store },
});
const sub = await mcp.experimental_events.subscribe({
  name: 'resend.email.received',
  arguments: { from: 'alice@example.com' },
  delivery: { mode: 'webhook', url: 'https://<your callback URL>' },
});
// TanStack AI doesn't renew by itself: call refresh({ key: sub.key }) before sub.refreshBefore. unsubscribe({ key: sub.key }) stops it.
```

**Success:** your handler answers `204`, and `onEvent` gets the event.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Subscribing fails with `CallbackEndpointError` (the bridge's challenge failed) | The callback must be HTTPS and reachable; with a local bridge, a path under a tunnel URL, served on the port the tunnel URL was created for |
| The receiver answers `401` | The store lost the subscription (memory store and a restart), or the request was re-serialized: pass the raw body |
| The receiver answers `400` for every delivery | Check the bridge's version: these libraries need `webhook-id` to equal the `eventId`, as the bridge sends it |
| Mastra or TanStack AI says the server doesn't support events | Both read `extensions["io.modelcontextprotocol/events"]`, which the bridge declares from 0.3.0: upgrade the bridge |
